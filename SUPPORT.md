# Support

These projects are shared in the hope that they’ll be useful. They don’t come
with a staffed support desk—or, for that matter, a support desk with anyone
sitting behind it. Here’s how to get a question or problem to the right place.

## Bugs and project-specific problems

For a reproducible bug, use that project’s issue tracker. Before opening a new
issue:

1. Check the README and other project documentation.
2. Search open and closed issues for the same problem.
3. Try the latest release or default branch when practical.

Include the project version, relevant environment details, steps to reproduce,
what you expected, and what happened instead. A small example or repository is
often more useful than a large screenshot—though screenshots, recordings, and
error output can all help when they add context.

## General or private questions

If your question isn’t a reproducible project bug, or it includes information
that shouldn’t be public, use [my contact form][contact]. Please include a link
to the project and enough context for me to understand what you’re trying to do.

Don’t send suspected vulnerabilities through a public issue. Follow the
[security policy][security] instead.

If an accessibility barrier is making a project difficult or impossible to
use, please read the [accessibility statement][accessibility] and let me know.
You don’t need to diagnose the underlying code before reporting the problem.

## A note on availability

I maintain these projects in my own time, and their activity levels vary. I
can’t guarantee a response, a response time, or a fix. Clear, focused reports
make it easier for me—or another contributor—to help when capacity allows.
